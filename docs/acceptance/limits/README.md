## 线上实测（真实模型，三个测试账号；脚本 `.claude/live-limits.mjs`，未入库）

14 项全部通过：

1. 主人的 Agent 视图里有额度和今天已花；群成员看到的群信息里没有这两项。
2. 额度没用完时，别人 @ 得到回复。
3. 一条付费模型的回复花了 4.0194 点，超过设成 1 点的额度；主人视图显示已花 4.0194。
4. 之后别人 @ 不再回复；群里出现一行“「××」今天的额度已用完”；再有人 @，不出现第二行。
5. 主人自己 @ 照常回复，且不计入“别人 @ 已花”。
6. 把额度调到 50，别人 @ 立即恢复；设成“不限”存为空值。
7. 同一个人一分钟内第 6 次叫别人的 Agent 被拒绝（前 5 次里有 1 次是对另一个 Agent），只有他自己的发送结果里带提示；别人读到的同一条消息不带；另一个人此时 @ 照常得到回复。

没有在线上测的：借道（A 的 Agent 转叫 B 的 Agent）的归属和拉黑、并发分配、排队中的回复在开始写前被额度拦下。这些只有自动测试覆盖。

## 部署前核对

- 验收环境没有单独设置任何 `AGENT_*` 上限变量，全部用新默认值（主人 4 条其中别人最多 3 条、全站 16 条、每分钟 20 / 20 / 5）。
- 内存上限 24 GB，当前占用约 0.15 GB；16 条同时处理附件的最坏情况约 1.6 GB。
- 付费模型一条回复的预留约 28.7 点（输出上限 4096 × 每 token 7000 微点），大于默认额度 20 点：这就是“额度只按实际花费算、不算预留”的原因。
