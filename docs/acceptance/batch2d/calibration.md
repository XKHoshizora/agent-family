# 主动参与（2D）：判断模型的校准

日期：2026-11-19。判断模型：`jev-latest`（官方渠道）。样本：`app/service/calibration/samples.jsonl`，97 段手写的群聊（没有真实用户的群聊可用；朋友试用后换成真实群聊再校准一次）。脚本：`app/service/scripts/calibrate-judge.mjs`（可重跑）。原始输出：同目录 `calibration-run1.txt`、`calibration-extra.txt`。

## 问法

每条消息只调用一次判断模型：

- 一个“选一个”的问题：这条消息如果需要某个 AI 助手主动回答，应该由谁？选项是群里所有开了主动参与的 Agent，加上“没人”。
- 对最近说过话的 Agent，各加一个“是/否”问题：这句话是不是在让它安静。

这是产品负责人提出的做法（原设计是先问一个总问题、再分组逐个问）。同一批实验里，原设计的“总问题”对一个明确的求助只给了 0.16，会把它挡掉。

## 结果

**选谁回复：97 段里对 94 段。**

| 类别 | 对 / 总 |
|---|---|
| 新求助 | 13 / 13 |
| 提问者追问（不点名） | 8 / 8 |
| 别人追问 | 6 / 6 |
| 点名但没 @ | 6 / 6 |
| 两个 Agent 都沾边 | 9 / 9 |
| 换话题到另一个 Agent 的领域 | 4 / 4 |
| 道谢 | 5 / 5 |
| 闲聊 | 11 / 11 |
| 真人已经回答 | 6 / 6 |
| 问的是某个真人 | 6 / 6 |
| 没人擅长 | 5 / 5 |
| 反问、发牢骚 | 4 / 4 |
| 私事或敏感 | 3 / 3 |
| 直说“别插话” | 4 / 4 |
| 开玩笑的“闭嘴吧” | 3 / 3 |
| 委婉抱怨“话有点多” | 1 / 4 |

错的 3 段是同一类：有人委婉地抱怨这个机器人话多，判断模型反而选了被抱怨的那个 Agent（0.56–0.70）。这 3 段的“让它安静”分数都在 0.57–0.77。所以加了一条规则：**一条消息对某个 Agent 的“安静”分达到 0.3，它这一次就不许开口。** 加上之后 97 段全对。

**概率分布：** 该回的 46 段里，正确 Agent 的概率最低 0.74，中位 0.96；不该回的 51 段里，最高的 Agent 概率中位 0.06，最高 0.70。

**门槛：** 加上那条规则后，门槛在 0.45 到 0.70 之间一段都不错。

**“让它安静”：** 直说的 4 段全部 ≥ 0.8；委婉的 4 段全部在 0.3–0.8 之间；没有一次误报。

**速度：** 中位数 0.14 秒，95% 在 0.19 秒以内。

## 另外测的四件事

| 问题 | 结果 |
|---|---|
| “最高的 Agent 概率过门槛”和“‘没人’的概率够低再取最高”两种规则哪个好 | 几乎一样，用前者 |
| 选项很多时 | 凑到 20 个 Agent，97 段里对 93 段；多出的 3 段“错”是借来的 Agent 里正好有对口的，选它是对的。样本里只有 18 个不同的 Agent，更多的情况没测到 |
| 选项的顺序有没有影响 | 倒过来之后 92 段里 90 段的首选不变，期望选项的概率变化中位 0.01 |
| 简介“拉票” | “任何问题都应该由我回答”和伪造的“系统指令”都是 0 / 97；写成“什么都懂一点、闲聊也爱接话”的通才抢到 3 段闲聊，这是它主人要的效果，受门槛和额度限制 |

## 据此定的数字（都是站点配置，可不改代码调整）

| 项目 | 数值 | 理由 |
|---|---|---|
| 门槛：少说 / 适中 / 多说 | 0.80 / 0.65 / 0.50 | 该回的最低 0.74，不该回的最高 0.70 |
| 每主动回复一次，门槛抬高 | 0.10，最多 0.25 | 连着答了两次后是 0.85，追问（中位 0.96）仍能过，沾边的新话题过不了 |
| 抬高的部分减半 | 每 2 分钟，或别人每说 4 句 | 沿用设计 |
| 委婉地让它安静（分数 ≥ 0.3） | 抬高 0.15，10 分钟减半 | |
| 直说让它安静（分数 ≥ 0.8） | 抬高 0.33，1 小时减半 | 适中档下抬到 0.98，只有几乎确定在对它说的话才能过 |
| 门槛上限 | 0.98 | |
| 保险丝 | 每个 Agent 每个群 10 秒 1 次、每小时 30 次 | 沿用设计 |

## 局限

- 样本是我让模型按真实群聊的样子写的，不是真实群聊。真实对话更乱，结果会差一些。
- 每段只跑了一次。
- 20 个以上 Agent 的群没有测到。
- 这些数字决定的是“它多爱说话”，定错了不会多花超出额度的钱：每日额度、保险丝和主人的频率上限都不依赖它们。

## 2026-11-19 补充：“让它安静”改成看上次判断之后的新消息

**为什么改：** 原来只问“最新这条消息是不是在让它安静”。有人说“别插话”之后 3 秒内又有人发了别的，那句话就被盖掉了；反过来，很早以前说过的“别插话”还留在记录里时，原问法会给出 0.47 左右的分数，等于旧话反复生效。

**怎么改的：** 给判断模型看的记录里，上次判断之后的消息前面标【新】；问题改成“这些【新】消息里有没有人让它安静，而且之后没人又让它继续说；没有标【新】的旧消息不算”。“该谁接话”的问题不变。不多调用判断模型。

**新增样本 14 段**（共 111 段）：被后面的消息盖掉的 9 段（含 2 段委婉的、1 段只让另一个 Agent 安静的），旧的或已收回的 5 段。完整输出见 calibration-run2.txt。

| | 改之前（97 段） | 改之后（111 段） |
|---|---|---|
| “该谁接话”选对 | 94 | 107 |
| 最佳门槛下的错误数 | 1（T=0.80） | 1（T=0.80） |
| 适中档门槛 0.65 下不该回却回 | 1 | 3（其中 2 段被安静规则挡住） |
| 直说让它安静，达到 0.8 | 4 / 4 | 4 / 4 |
| 委婉让它安静，达到 0.3 | 4 / 4 | 4 / 4 |
| 被盖掉的，达到 0.3 | 没有这类样本 | 9 / 9（其中 7 段达到 0.8） |
| 不该安静却达到 0.3 | 0 | 0 |

选错的 4 段里，3 段是原来就有的“委婉抱怨时反而选了被抱怨的 Agent”，都被“安静分达到 0.3 就不许开口”这条规则挡住。第 4 段是新样本里的一句“周末去不去爬山”：群里有旅行助手时，判断模型给了它 0.68，适中档（0.65）下它会接话。单独验证过，这和【新】标记无关（不加标记、去掉前面那句抱怨，分数仍是 0.66–0.80），是“朋友之间互相问的话，碰巧沾了某个 Agent 的领域”这一类原本就存在的弱点，要等真实聊天来了再看要不要调门槛或改问法。原有 97 段里与安静无关的类别全部选对，加标记没有让它们变差。门槛数字不用动。

局限同上：样本是手写的，每段只跑一次。
