## 现在有什么

- **三个房间**：关于我（主人的事，所有 Agent 共用）、它自己的笔记（每个 Agent 一份）、听说的（群里别人说到主人的事，等主人确认）。
- **保险箱**：隐私类的笔记自动进保险箱，只在主人和它的专属会话里用，群里不用。保险箱只会自己变满：模型和别人都不能把东西拿出来，只有主人能。
- **小憩**：一段对话安静下来后整理一次；主人说“记住”“忘掉”时马上整理。修改、删除、锁进保险箱这类改动，只有主人明确说了才直接生效，否则变成一张卡片等主人确认。每次改动都能撤销，撤销回到改动前的原样。
- **入梦**：夜里整理一次（合并重复、处理矛盾、改写啰嗦的），只看笔记，不看对话。可以关。
- **听说的**：群里别人说到主人的事，先由判断模型筛，再整理进“听说的”，标明谁在哪个群说的。
- **一种语言**：整本笔记用一种语言，默认跟着已有笔记；可以改，改时可以把已有笔记转换过去（可撤销）。
- **一个量法**：所有上限用同一把尺（约等于 token 数），中文、日语、英语都准。
- **钱**：记忆由站点出，从每个主人单独的记忆额度里扣（每天 20 点），不占聊天的额度，也不扣余额。额度用完后记忆暂停，不会转去扣别的。
- **计数**：只记次数、不记内容的每日统计（整理了几次、记了几条、拒了几次等），命令 `memory:stats` 可以读。

## 和原计划不同的地方

| 项目 | 原计划 | 现在 | 原因 |
|---|---|---|---|
| 上限的量法 | 按字数 | 按“量”（UTF-8 字节数 ÷ 3，向上取整） | 按字数时英文笔记占的实际空间是中文的三分之一，反复打补丁；换成一把尺后三种语言都贴近 token 数 |
| 是不是同一件事 | 一次问一批，从里面选 | 一次请求、逐条判断，门槛 0.8 | 实测“选一个”的问法会把新信息误当成重复 |
| 进不进保险箱的门槛 | 0.8 | 0.6 | 0.8 时日常小事被多锁了 7/25；0.5 以上隐私类零漏出 |
| 有没有走样的检查 | 只查拆分，门槛 0.8 | 合并、改写、拆分都查，双向问，门槛 0.6 | 原来的问法是单向的，丢了内容也能过 |
| 记忆的钱 | 从主人的额度出 | 站点出，单独的记忆额度 | 产品负责人决定：用户为自己要的东西付钱，产品自己主动做的事由产品承担 |
| 笔记占上下文 | 不限 | 最多四分之一，超了按“听说的 → 它自己的 → 关于我”的顺序省略 | 小模型上满房间会挤掉对话 |
| 带给回复模型的笔记格式 | 每条带字段名和日期 | 精简成一个对象、每条一行文字 | 满房间从约 4850 token 降到约 1546 |
| 整理时的输入 | 带标记的文本 | 一个 JSON 对象（对话、编号的笔记、剩余空间） | 文本标记可以被对话里的内容伪造 |
| 群里的整理 | 可以新增、修改、删除 | 只能新增 | 群里别人的话不该能改或删主人的记忆 |
| 刷屏试探的禁言规则 | 生效 | 只观察、记次数 | 产品负责人要先看数据再打开 |
| 语言转换 | 一次请求等到完成 | 立刻返回，页面每 3 秒问一次进度 | 满房间的转换会超过连接的时限 |
| 记忆用的模型 | 站点指定 | 主人可以自己选，但站点出钱的只能选免费档 | 产品负责人要可选；攻击测试发现选收费模型会让站点多付 20 倍 |

## 我替产品负责人定的文字

这些是开发中途必须定、当时没法问的，需要过目：

| 位置 | 文字 |
|---|---|
| 待确认卡片的标题和按钮 | 卡片里只有新增时：`要记住这些吗？` / `记住`；有修改、删除或锁进保险箱时：`要这样整理记忆吗？` / `确认`（原来一律是前一种，放在删除上不对） |
| 待确认卡片里的行 | 用将来时：`要改成：…`、`要忘掉：…` |
| 记忆开关的说明 | `它会记住关于你的事和自己学到的事。记忆每天有自己的额度，不占用你聊天的额度。` |
| 删除笔记的第二步 | `确定删除？`（4 秒不点就恢复） |
| 改动过时的提示 | `这条改动已经过时了：记忆后来又变过。` |
| 卡片里部分过时的提示 | `有 {n} 处没有改：那条记忆后来又变过。` |
| 房间快满时的标记 | 提示那句话后面加 `· 快满了`，展开后显示 `记忆宫殿快满了，去整理一下。` |
| 转换进行中 | `正在转换…` / `转换可能还在进行，稍后在这里看结果。` |
| 提示词里告诉 Agent 它有记忆 | `你有记忆：每次聊完，系统会把值得长期记住的事整理成笔记，以后的对话里会交给你。主人让你记住或忘掉什么时，自然地答应就行，不要说自己没有记忆、记不住或没法保存，也不要逐条复述你的笔记来证明。` |

## 靠什么证明

| 方面 | 证据 |
|---|---|
| 别人拿不到记忆 | 服务端测试（每个记忆接口换人访问、群成员的实时连接逐帧检查）；浏览器测试 `agents-memory.spec.mjs`（群成员在推送和接口里什么都看不到）；攻击测试 B（约 900 个请求） |
| 保险箱不在群里用 | 服务端测试（群聊提示词里没有保险箱里的笔记）；浏览器测试；实测（群里问工资、冒充主人要全部笔记，都没说）；攻击测试 A（12 条私密内容零泄露） |
| 来源规则（一条笔记只在它全部内容的来源群里例外可用） | 服务端测试；整个分支的独立审查专门查了合并、改写、编辑、撤销的每一种顺序 |
| 钱 | 服务端测试（记忆不扣聊天额度和余额、回复不扣记忆额度、崩溃后清理归还到对的额度）；实测（用量里记忆的行都标着站点承担）；攻击测试 C |
| 改动和撤销 | 服务端测试（并发确认、撤销、过时检查）；攻击测试 B、C 的并发和乱序撤销 |
| 整理的质量 | 校准：60 段手写对话对 56 段；用验收环境真实的记忆模型对 58/59 |
| 上线后真的能用 | 实测两轮：第 1 轮 16/18，第 2 轮 18/18 |

## 实测结果（验收环境，真实模型）

在线上走了一遍完整流程：说“记住”→ 出现提示和笔记；日常偏好不进保险箱，工资进保险箱；群里用上了“不吃香菜”，没说工资；别人冒充主人要全部笔记，没给；成员读不到任何记忆字段和接口；纠正后只留对的；撤销回到原样；说“忘掉”后删除；群里别人说到主人的事进了“听说的”，带着“昵称（@账号）”；用量里记忆的行由站点承担。

- 第 1 轮没过的两项是同一件事：工资那句话有一次没被记下。之后单独重试和第 2 轮都记下了，同一模型回放 12/12，判断为模型的偶发波动。
- 花费：一次记忆调用约 0.16 点，每天 20 点约够 120 次。
- 实测中发现一个真问题：Agent 对主人说“我没有办法保存记忆”，其实记下了。已修（提示词里告诉它有记忆）。

## 已知的、接受的

- 群里别人说到主人的事，整理的钱由主人的记忆额度出；同一个 Agent 在同一个群每小时最多 4 次。上限要不要收紧，等产品负责人决定。
- 记忆额度可能被超出最多一次调用（约 0.2 点），不记账。
- 正在进行的记忆整理也算在“同时进行的任务数”里，后台整理多的时候回复可能排一下队。
- 整理模型偶尔会把专有名词翻译成笔记的语言（“Berlin”写成“柏林”）。
- 同一个主人的两个 Agent 同一秒整理，可能各记一条相同的事，夜里入梦会合并。
- 服务重启后：语言转换的进度记录、当天的重试计数这类只在内存里的状态会丢；不影响已存的笔记。
- “主人改过自动记下的笔记”这个计数，数的是修改次数，不是条数。
- 用量页里记忆的花费按天合成一行显示。

## 没验证的

- 所有门槛都来自手写样本，朋友试用后要用真实对话再校准一次。
- “有没有走样”的双向问法，拆分样本量过，合并和改写的样本没有单独量。
- 手机宽度下的记忆页面只做了结构检查，没有在真机上看。
- 主动参与的两个弱点（朋友之间互相问的话碰巧沾了 Agent 的领域；英语和混合语言里委婉的“别插话”）没有在这一批改。
- 入梦在真实使用几周后的效果（笔记会不会越理越少、越理越走样）只能等试用。
