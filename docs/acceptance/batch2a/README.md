### 独立核对（第 23 项）

**设计要求的是**：一位没参与实现的审查者拿到代码和运行中的服务，专门尝试突破第 11 到 22 项，直到一轮下来没有新的可利用问题。

**实际情况**：我两次派出这样的审查，都在刚开始时被模型自带的安全过滤拦停（它把“攻击我们自己的服务”判成了网络攻击行为），没有产出。我没有自己绕过去做。改为做了一次范围更窄的**独立规则核对**，由没参与实现的审查者完成：

- 逐条阅读第 11 到 22 项对应的代码和测试，判断测试是否真的能证明规则。
- 用它自己注册的三个账号，在验收环境上用普通的登录请求实际验证“谁能看到什么”这类规则。
- 第 16（地址防护）、19（模型出错）、20（重启）、22（排版显示）四项**只核对了代码和测试，没有在线上做试验**。第 22 项另有任务 5 的四轮专门审查，在真实浏览器里实测过。

结论：**12 项规则全部成立，没有发现严重或重要问题**，发现 12 个轻微问题。

## 你会注意到的地方

1. 回复出现时先是纯文字，一瞬间后变成排版好的样子。
2. **每个链接后面都带着它真实的网站名**，例如“文档（example.com）”，直接贴出来的网址也一样。这是为了让 Agent 的回复无法把链接伪装成别的网站。
3. 公式只认 `$$…$$`；单个 `$` 不当公式，免得“$5 和 $10”被吃掉。
4. 特别大的表格、公式很多的回复会保持纯文字并附一句说明；html/xml 代码不高亮。
5. 逐字回复超过 2 万字时，之后只提示“仅显示开头部分”。保存下来的回复最长 8 000 字。
6. 与 Agent 的对话里也有“已读”；Agent 暂停时你的消息停在“已发送”。
7. Agent 只能看 PNG、JPEG、WebP 图片；GIF 只告诉它文件名。
8. Claude 系列在没有人设时会自称“Claude Code”（平台那边的原因）；写了人设就按人设来。
9. 和原型相比少了“附件”“电脑”等行，因为这一批还没有工具和设备。

## 已知限制

- 第 23 项独立攻击测试未按原定形式完成（见上）。
- Gemini 接口未对真实模型验证。
- 站点模型没有开 PDF 和“高”以上的思考档位（没验证过的能力先不开）。
- 备份恢复演练本批没有重做。
- 没有核对 Railway 代理的空闲超时是否大于“留空自动起草”的最长等待（约 110 秒）；实测回复在 3 到 5 秒内。
- 一个会话里有上百条特别长的消息时，打开会有 0.5 到 1.5 秒的停顿（纯文字排版本身的开销）。
- 排版后台线程启动失败时，已经在屏幕上的消息保持纯文字，重新进入会话才恢复。
- 会话列表的预览行是按规则去掉排版符号的，个别写法（如 `__init__.py`）会被误处理。
- 仍然只能运行一个实例；余额只能由管理命令发放（充值是以后的批次）。
