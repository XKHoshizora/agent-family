# 第 2A 批：我替你做的决定（共 45 条）

说明：这些决定是在你休息期间由我替你做的。每条写明三件事：决定了什么、为什么、如果错了要付出什么代价。后来被更新或被你本人的决定替换的，这里只写最终结果。工作记录里没有写原因或代价的地方，如实写“未记录”。

## 一、产品上你能看到或感觉到的

1. 别人的 Agent 的编号如果被拿去在群里使用，系统的回答和对待“不是好友的人”完全一样（返回“无权访问”）。原因：这符合规格书里“Agent 对外不可见”的规则，原计划写的“请求有误”是错的。代价：账本写明没有代价。

2. Agent 对外完全不可见，没有任何例外：头像接口和屏蔽接口对非主人（或所有人）都像对一个随机编号那样回答。原因：账本只说明这比规格书 6.1 节原先保留的两个例外更严格，规格书文字之后要改。代价：以后第三批要放宽的话，改两处接口检查即可。

3. 暂停与停止的规则按规格书收紧：暂停会彻底结束正在进行的回复，排队中的回复也一并取消；暂停返回之后不再有任何新文字出现；主人手动停止的回复永远保持“已停止”；我们自己没能存下来的回复不收费。原因：审查指出这四点与规格书 6.2 和 6.5 节相矛盾，不是小修小补。代价：做得比需要的更严格，但没有危害。

4. 主人“重新开始话题”时，排队中还没开始的回复被悄悄结束为“已取消”，而不是显示“失败，服务忙”。原因：主人是自己选择重新开始的。代价：未记录。

5. 给模型看的对话，按“回答了什么”来排顺序：主人发了第 1 条，Agent 回复，之后主人又发了第 2、3 条时，模型看到的是第 1 条、回复、第 2 条、第 3 条。原因：之前打算丢掉末尾的 Agent 回复，那样模型会重复自己说过的话。代价：排序的代码可以再简化。

6. 发给模型的图片只有 PNG、JPEG、WebP 三种会真正把图片内容发出去，GIF 只按文件名告知模型。原因：四种对接协议都接受这三种格式。代价：本来能看 GIF 的模型就看不到 GIF 了。

7. Agent 的回复如果被中途停止或截断，从第一个 `<af-` 开始的内容全部丢掉，不会把原始标记显示出来。原因：不显示原始标记，并且与流式显示时用户已经看到的内容一致。代价：未记录。

8. 超过每分钟回复次数限制时，不再悄悄不回，而是出现一条“失败、可重试”的回复记录（原因标为超过频率），主人能看到并重试；消息本身照常保存。原因：消息石沉大海又什么都不显示，正是规格书禁止的失败形态。代价：要拿掉的话是删一个分支。

9. 重新连上网络时，如果某条回复仍在生成，界面只显示“正在回复…”，不显示一个从半句话开始的气泡，直到完整消息到达。原因：实现者提出的顾虑，避免半句话开头的气泡。代价：一个分支。

10. 与原型相比，几处没有逐条列出的差异被接受：没有“附件”和“电脑”行、“参与的会话”只有一行、暂停提示里没有任务字样、标签用“未选模型”和“只能查看”、已删除的提示、字数超限在行内提示、两条提示语。这些差异会写进给你看的验收记录。原因：本批次没有任务、设备和附件能力，这些差异是自然结果。代价：要恢复的话是改回文案。

11. 在与 Agent 的对话里显示已读回执；如果 Agent 被暂停或设为“只在被提到时回复”，主人的消息一直停在“已发送”。原因：Agent 的已读标记在通信里确实存在。代价：改一个条件。这一点也写进验收记录。

12. 单个美元符号的行内公式关闭：`$5 和 $10` 保持为普通文字，只有用两个美元符号包起来的才渲染成公式。原因：聊天里出现价格远比出现行内公式常见。代价：一个开关；模型发来的 `$x$` 暂时不会渲染。这一点写进验收记录。

13. 回复内容的格式化（Markdown 显示）整体改为在独立的后台线程里进行，设 250 毫秒硬性期限，超时就终止并显示纯文本；主界面只检查并显示有数量上限的结果；只有看得见的消息才做格式化，每个视图最多 30000 个元素；流式生成时最多每 300 毫秒请求一次；单条文本最多 3000 个元素、表格最多 600 个单元格；不再高亮 html 和 xml 代码。你会感觉到：回复先以纯文本出现一瞬间再变成带格式；特别大的表格、代码或公式很多的回复保持纯文本并带一句说明。原因：连续三轮逐个堵输入都留下新的放大漏洞，而在同步计算之后才检查的防护无法限制那段计算本身。代价：工程量比需要的大，链接看起来更繁。这个决定取代了此前“每条消息最多 5000 个表格单元格”和“逐个堵输入”的做法。

14. 每一个链接后面都显示它真实的网站域名，没有任何例外，裸地址也一样（例如显示 `https://a.example/x（a.example）`）；提示框永远显示真实目标；带用户名密码的地址不当作链接；链接文字压平成纯文字、最多 200 个字符、里面不渲染公式；方向控制字符被去掉。原因：这是经过多轮才收紧到底的结果，每一个“看起来一样所以免标注”的例外都被证明可以伪造，通过 Agent 回复进行钓鱼是最现实的滥用。代价：写成 `[example.com](https://example.com)` 会显示成“example.com（example.com）”，略显重复但诚实。

15. 已缓存的格式化结果和新生成的一样遵守“只渲染看得见的消息”，每一帧最多把 3000 个元素变成带格式。原因：重新打开对话时缓存结果曾一次占用 386 到 585 毫秒。代价：未记录。

16. 流式生成中的气泡最多保留并显示开头 20000 个字符，之后显示一句“仅显示开头部分”，完整消息到达后替换它；已保存的回复本来就最多 8000 个字符。原因：已保存的回复本来就有上限，而且原先的措辞“完整结果”是不真实的。代价：特别长的回复在结束之前看不全；提示语措辞本身的代价未记录。

17. 站点模型的参数：每次最多输出 4096 个词元，对话长度上限免费档 64000、付费档 128000，支持看图，不支持 PDF，思考强度只提供“低”和“中”。原因：只打开已经对真实供应商验证过的能力，这些模型真实的长度上限我并不清楚，所以故意取得偏低。代价：长对话被缩短得比需要的早、站点模型拒绝 PDF、不提供“高”思考强度；每一项都只是改一处配置。

## 二、计费与额度

1. 验收环境的站点模型和价格：一点等于上游标价的 0.001 美元。免费档是 `gpt-6-luna` 和 `claude-haiku-5-5`，付费档是 `gpt-6-sol` 和 `claude-sonnet-5-5`；免费档每个输入和输出词元分别是 70 和 350 微点，付费档是 1400 和 7000 微点；每人每天免费 100 点（最多约 0.10 美元）；预置账户各送 2000 点。接口方面，你本人亲自决定：GPT 系列能用 Responses 接口就不用 Chat Completions，所以 `gpt-6-luna` 和 `gpt-6-sol` 用 Responses，`claude-haiku-5-5` 和 `claude-sonnet-5-5` 用 Anthropic 接口；这取代了我先前“不对站点模型使用 Responses”的决定。原因：便宜的模型让免费档成本可以忽略；按上游成本计费意味着没有利润。代价：数字都在配置里，不用改代码；在上游问题未修复期间，每条 GPT 回复比真实内容多花约 0.31 点（免费模型）或约 6.2 点（付费模型）。你说过 CanalAPI 是你自己的平台，发现的问题报告给你来修。

2. 一次站点调用最多只收它预扣的数额，超出部分免收，但用量记录里仍保留真实成本。原因：这样“最多欠一条回复的债”的上界无条件成立，用户永远不会被收到超过预估的钱。代价：站点要自己承担低估的部分（在用量记录里看得到）。

3. 用量接口里“最近记录”显示的点数，是用户被扣掉的数额（免费额度加余额），而不是真实成本。原因：用户把它当成“我用掉了多少”来读。代价：改一个数据库表达式。

4. 管理命令里扣减额度（负数的赠送）应当记为“调整”。原因：让账本诚实。代价：未记录。

5. 三个管理上的默认处理被接受：赠送 0 点被拒绝；查看账户和改档位的命令拒绝对 Agent 名称操作；未知档位按免费档的限额处理。原因：都是合理的默认做法。代价：各改一行。

## 三、安全与隐私

1. 向 OpenAI 的 Responses 接口发请求时设为不存储（`store:false`）。原因：第三方手里少留用户对话的副本，而且没有任何功能依赖对方存储。代价：去掉一个选项即可。

2. 你真实的供应商密钥不允许由自动化浏览器敲进任何网页表单；站点模型的密钥作为变量交给 Railway，用户供应商的连通检查由脚本通过服务接口创建；这把密钥按“正式”处理，验收环境的网址也不带测试标记。原因：账本写明的依据是密钥属于正式密钥，且该主机没有测试标记。代价：你需要手动多做一步。

3. 已保存的供应商密钥要和它所在的那一行数据绑定，被复制到别的行或别的主人名下就无法打开，调用会按“供应商拒绝”处理。原因：目前还没有任何已保存的密钥，所以现在做没有代价，以后再做就要迁移数据。代价：没有。
