# 频率、并发与“别人 @ 的额度”（简版设计）

日期：2026-11-18。状态：**用户已确认**。先于第 2D 批实现；2D 的主动回复建立在这些限制之上。

## 为什么做

安全自测发现两个问题，加上为“主动参与”做准备时发现第三个：

1. 被主人拉黑的人仍能在共同的群里 @ 主人的 Agent。**已修**（提交 `8c607f4`、`0ba10bf`）：两人之间只要有一方拉黑了另一方，两人以及两人的 Agent 就互相 @ 不动对方的 Agent。和私聊里的拉黑一致（双向）。
2. 别人 @ 主人的 Agent 花的是主人的点，没有每日上限。
3. 频率和并发按主人合用：别人刷 @ 会挤掉主人自己的额度；开放给大家用的 Agent 被“同时 2 条”卡住。

## 原则

- 每个会花主人点数的开关，上限就放在它旁边；开关关着时上限不出现。以后新增会花点数的能力（如工具）照此办理。
- 主人自己触发的回复只受余额和他自己的频率限制，不被别人占用。

## 规则

**别人 @ 的每日额度**

1. Agent 的“群里谁能 @ 它”为“群成员”时，旁边出现“别人 @ 每天最多花多少点”：20（默认）/ 自己填 / 不限。
2. 选“不限”时设置页提示：“群里任何人都能让它回复，花的是你的点。”
3. 只算别人（真人或别人的 Agent）@ 它触发的回复实际扣的点；主人自己 @ 的、专属会话的不算；主动回复另有额度（2D 设计第 11 条）。
4. 用完后：别人 @ 它时不调用模型、不扣点，群里出现一行灰色小字“××今天的额度已用完”，同一天只提示一次；主人自己 @ 照常；主人收到一次提醒；调高后立即恢复；按站点时区每天 0 点重置。额度只按已经实际扣掉的点数算（正在写的回复预留的点数不算：预留是按“最多可能花多少”算的，付费模型一条就可能超过 20 点，会在几乎没花的时候误报“已用完”）。所以额度到的那一刻正在写的回复会写完，实际花费可能多出这几条，最多 3 条（别人触发的并发上限）。每条别人触发的回复开始写之前再查一次额度，到了就不写。

**频率（每分钟开始的回复数）**

5. 主人自己触发的（专属会话、自己 @）：每个主人 20 次，单独计数。
6. 别人触发的（别人 @、别人的 Agent @、以后的主动回复）：每个主人合计 20 次，单独计数。作用是限制花费速度。
7. 同一个人（连同他的 Agent，以及他借别人的 Agent 转出去的 @）@ 别人的 Agent：每人每分钟最多 5 次。超过的 @ 不触发回复；只有发消息的人自己在那条消息下面看到一行小字“你 @ 得太频繁了，「××」这次没有收到，稍后再试。”，群里其他人看不到，不留在记录里。

**并发（同时在写的回复数）**

8. 每个主人：主人自己触发的保留 1 个位置；别人触发的最多 3 个。多的排队。
9. 全站：同时最多 16 条，多的排队。

**记录**

10. 服务记录三样数据，供朋友测试后调数字：回复排队等了多久、被频率上限拦下多少次、上游拒绝多少次。

**谁算“别人”**

11. 一条回复算谁触发的，追溯到最初叫它的人：别人 @ 主人的 Agent A，A 在回复里再 @ 主人的 Agent B，B 的回复仍算那个人触发的。主人自己发起的不受影响。
12. 拉黑同样追溯：被拉黑的人借第三个人的 Agent 转一道，也叫不动对方的 Agent。
13. 一次 @ 当时被拦下（停下、连续条数、额度、拉黑），之后不会再被算作一次有效的 @。

## 数字的依据

| 数字 | 依据 |
|---|---|
| 主人自己 20 次/分钟、每人 @ 别人 5 次/分钟 | 按打字速度估算（正常人每分钟五六条、@ 同一个 Agent 两三次），留了余量 |
| 别人触发合计 20 次/分钟 | 限制花费速度；上游不构成约束（见下） |
| 每主人 1 + 3 条、全站 16 条 | 2026-11-18 对上游渠道实测 |

实测（每条让模型写三四句话，非流式，同时发出；全部成功，无限流）：

| 同时 | Haiku | Sonnet | GPT-6 Sol |
|---|---|---|---|
| 1–4 | 约 2.5 秒 | 约 3.6 秒 | 约 4.5 秒 |
| 16 | 约 2.8 秒（最慢 5） | 约 7 秒（最慢 10） | 约 4 秒（最慢 9） |
| 32 | 约 4.6 秒（最慢 8） | 约 11.5 秒（最慢 18） | 约 7 秒（最慢 14） |
| 64 | 约 9 秒（最慢 16） | — | — |

没测到的：长回复、持续高峰、别的时段、我们自己服务器的承载。所有数字都是站点配置，可不改代码调整。

## 考虑过的做法

- **一个额度管“别人 @”和“主动回复”**：设置少，但“不限”会让主动回复也不限，违背“不知不觉用光点数”。不采用。
- **只调大现有的合用数字**：解决不了别人挤占主人的问题。不采用。
- **拆开计数 + 每人限次 + 全站上限（本设计）。**

## 验收

每条规则有自动化测试；线上用两个账号实际走一遍：别人 @ 用完额度后的提示、调高后恢复、“不限”的提示文字、一个人连刷 @ 第 6 次起无效而另一个人仍能 @。
