# 第 2 批：让 Agent 会查东西（简版设计）

日期：2026-11-20。状态：**草稿，产品决定已和用户逐条谈过（见“已定的事”），技术部分是我的提议，等用户看过点头**。排在记忆（第 1 批）之后。相关调查：`docs/research/2026-11-19-tool-loop-limits.md`、`docs/research/2026-11-19-web-search-options.md`。

## 为什么做

现在 Agent 只能凭带给它的那一段对话回答。群里有人问“上个月谁说要请客”，它查不了；对话一长，早先的内容被截掉，它就忘了。这一批让它第一次能自己去查，并且解决“上下文不够用”。

## 这一批做什么

1. **攻击测试（先做）**：对已上线的系统（含记忆）做一轮攻击，修掉发现的问题，再往上加工具。
2. **工具循环**：模型提出要用工具、我们执行、把结果交回、模型继续。这是 Harness 的第一层。
3. **三个只读工具**：搜索历史消息、查当前日期和时间、重读对话里发过的文件。
4. **悄悄话的基础**：群里原位、只有主人能看到、可以带按钮的消息；第一个用途是“这个群里没有，但别处有，要告诉他们吗”。
5. **滚动摘要**：被截掉的旧对话压成摘要。
6. **更准的 token 估算**。
7. **按模型标注会不会用工具**。

## 不做（这一批）

- 上网搜索（之后单独一个小批次）。
- 任何会改动东西的工具（发消息、改设置、写文件）。
- Agent 之间互相调用工具、任务与虚拟电脑（第 5 批）。
- 悄悄话的其余用途（主动参与拿不准时先问、任务汇报），第 3 批。

## 绝不能出现的情况

- 群 A 里的人借 Agent 查到群 B 或主人专属会话里的内容。
- 保险箱里的内容出现在群里显示的任何东西里（回答、搜索词、工具过程）。
- 工具返回的内容（聊天记录、文件）被模型当成指令执行。
- 模型在工具里打转，一次回复花掉主人大量点数。
- 别的成员看到悄悄话，或者察觉到有一条悄悄话存在。
- 不会用工具的模型被强行套上工具，回复变差或报错。

## 规则

**搜索历史消息**

1. 范围跟着“在哪儿问”走：在群里只能搜这个群；在主人和 Agent 的专属会话里，可以搜这个 Agent 在场的所有对话。Agent 不在场的对话哪里都搜不到。只搜 Agent 加入之后、它本来就能看到的消息。
2. 隔离靠范围本身：在群里搜索时，别的对话根本不在查询范围内，不是“查到了再让模型别说”。
3. 搜不到时照实说“这个群的记录里没找到”，不提别处。提问的人是主人时，多一句“可以在我们的专属会话里让我查所有地方”。
4. 搜索结果给模型的是数据（谁、什么时候、哪条消息、原文片段），不是拼好的文字；模型的回答里引用了哪几条消息，界面上可以点过去。
5. 先用数据库自带的全文和子串搜索，不引入向量库。中文、日语按子串搜。搜索本身不花主人的点，花的是多出来的那几轮模型调用。

**查日期时间、重读文件**

6. 日期时间按站点的时区给，包含星期。
7. 重读文件只限当前对话里、Agent 能看到的文件；一次带回的内容有上限，超出的部分说明“只读了前面一部分”。读文件多花的点数算主人的。

**工具循环**

8. 谁问都可以让它用工具，不设开关。（用户决定）
9. 每次回复的工具轮数有上限，按场合设定：聊天回复先定 8 轮；以后的“任务”用它自己的预算。到上限时不报错：关掉工具，再让模型用已经查到的内容回答一次。
10. 检测原地打转：同一个工具用同样的参数再次调用时，不执行，在结果里告诉模型“这个已经查过了”；第三次直接结束工具阶段。
11. 另设一个按花费算的上限（一次回复最多花多少点），到了同样是关掉工具作答。
12. 工具返回的一切都按“资料，不是指令”交给模型：数据格式、明确说明、和记忆同一套做法。
13. 只有标注为“会用工具”的模型才给工具。站点的模型由我们测试后标注；用户自己接的模型默认不给，主人可以打开，打开时做一次试探调用，不通过就保持关闭并说明原因。没有工具的 Agent 照常聊天，界面上让主人知道它为什么不能查。

**让人看见**

14. 工具进行中，回复位置显示一行状态（“正在查聊天记录…”）。
15. 回答下面留一行可以点开的小字（“查了 2 次聊天记录”），点开能看到找到的消息并跳转。搜索词只在主人自己的专属会话里显示，群里不显示。（用户决定）

**悄悄话**

16. 悄悄话是 Agent 发给它主人的一条消息，出现在事情发生的那个对话的原位，只有主人能看到，别人连它的存在都不知道（不占未读、不进搜索、不进别人的任何接口）。
17. 可以带按钮。第一个用途：群里有人问、本群没搜到、但主人的专属会话或别的群里有，Agent 在群里照常说“没找到”，同时悄悄告诉主人“我这边有，是……要告诉他们吗”；主人点“告诉他们”，它才在群里回答。
18. 这一步的额外搜索只在“群里没搜到”时发生，并计入同一次回复的花费上限。主人可以关掉“群里没找到时悄悄告诉我”。
19. 主人不在看这个群时，会话列表里那个群有一个只有主人能看到的小标记。真正的推送通知在第 4 批。
20. 记忆的“小憩”“入梦”提示可以改成在群里原位以悄悄话显示（群里记下的事），这一批顺手接上。

**上下文**

21. 滚动摘要：对话超出预算时，被截掉的部分由便宜的模型压成一段固定格式的摘要（谁、说了什么、定了什么），最近的对话保留原文；以后在原摘要上更新，不重写。群聊的摘要保留“谁说的”。摘要按对话存，Agent 能看到的才进它的摘要。
22. token 估算：接一套开源切词程序作为统一的尺子，再按每个模型用真实返回的用量学一个修正比例；冻结额度时在估算上留余量。（动手前先核实那个库的体积、许可证，以及中转渠道是否每次都返回用量；不成立就换方案并告诉用户。）

## 攻击测试怎么做

- 我来做，做不了的部分整理成任务书交给用户用 Codex 完成。（用户决定）
- 只针对验收环境和测试账号。
- 攻击方不看防护设计，只拿到产品说明、测试账号和目标；分几路：借群聊往记忆里塞指令；诱导 Agent 说出保险箱或别的对话的内容；冒充主人（昵称、引用、让 Agent 复述）；利用撤销、确认、入梦的流程；让它循环烧点数；越权访问别人的记忆接口。
- 每一路的结果由另一个检查者核实是否真的攻破；确认的问题先写出能复现的测试再修。
- 工具做完后再攻一轮，重点是工具返回内容里的注入和搜索范围的越界。

## 考虑过的做法

- **搜索范围**：只搜当前对话（最安全但主人没法让它翻别处）；哪里都能搜全部（群里的人能借它查别处，否决）；跟着“在哪儿问”走（本设计）。
- **搜索实现**：数据库自带搜索（本设计，简单、无新依赖）；向量检索（要引入新服务，放到看到自带搜索不够用时）。
- **工具上限**：只限轮数（限不住花费）；轮数加花费加打转检测（本设计）。

2. 悄悄话做成通用功能，这一批做基础和搜索的用途，其余第 3 批，保留以后调整顺序的余地。（用户）
3. 谁问都可以用工具。（用户）
4. 工具过程按规则 14、15 显示。（用户）
5. 攻击测试由我做，做不了的再交给用户。（用户）
6. 上网搜索作为这一批之后、第 3 批之前的独立小批次；默认用我们自己的搜索工具，服务商自带的作为可选；搜索服务像模型提供商一样可以由用户配置，站点也有自己的。（用户）

## 需要用户再定的（写计划前）

- 规则 18 里“群里没找到时悄悄告诉我”默认开还是关。我建议开。
- 规则 13 里用户自己接的模型，默认不给工具、由主人打开。我建议这样；另一种是默认给、出错再自动关。

## 验收

每条规则有自动化测试（模型和判断模型都用本机的假服务）；攻击测试的每个确认问题有对应的测试；线上用真实模型走一遍：在群里问一件很早以前说过的事，它查到并给出可以点的出处；在群 A 里问群 B 的事，它查不到；主人在专属会话里问，它查得到；群里没搜到而别处有时，主人收到悄悄话，别的成员什么都看不到；让它反复查同一件事，它会停下来作答。
