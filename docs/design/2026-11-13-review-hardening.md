# Claude 审查修复决策

用户授权判断合理建议、测试后部署。本次处理上下文、LINE、额度，以及直接影响这些流程的点名／轮次边界；不增加主持、自动总结、持续讨论或执行环境。

- 上下文按任务组装：保留本次问题，每位有效前轮发言分配预算，最后用剩余空间装旧历史。含作者信息的 JSON 数据包区分资料与系统指令，自己的发言使用 assistant 角色；第二轮末尾追加明确任务。48,000 字符含包装和轮次指令，截断有标记。
- 单人点名优先于下拉默认；单人模式点多位则明确拒绝。讨论少于两人降为单轮；前轮有效回答不足两份不进入第二轮，失败者不参与第二轮。消息记录轮次，运行记录说明原因。
- 额度按最坏模型步骤预留：无工具一位每轮 1 步，有工具最多 3 步；使用才计入 calls，结束／失败／取消／重启释放剩余预留。开始日固定为 UTC 归属日；LINE 有独立步骤上限且仍受空间总限额约束。较保守但可保证工具不会挤占其他任务已保留额度。
- LINE 绑定使用唯一 scope 标识和消息序号边界。只读取本次绑定后的 LINE 对话，避免网页对旧资料的复述间接流入；默认关闭资料工具，明确开启后才可访问本群全部笔记与项目（含旧资料）。撤销工具共享会重新开始 LINE 上下文并使旧任务失效。旧绑定升级时采用新的安全边界。
- LINE 默认各自回答，可独立设置；帮助显示模式。仅回传最后实际轮次的完整回答，错误／取消用系统说明；LINE API 单次最多五条，不伪装成 Agent 成功回答。用户以群内稳定哈希后缀区分。
- 验证长上下文、五成员、失败／取消、并发预留、午夜／重启、绑定／撤权、无真实模型收费的 LINE 模拟端到端，以及浏览器设置／点名／预算提示。
