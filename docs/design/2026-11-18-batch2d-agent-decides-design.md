# 第 2D 批：Agent 自己判断要不要回复（简版设计）

日期：2026-11-18。状态：**草稿，等用户确认**。前置：第 2C 批（把自己的 Agent 拉进群）已上线。

## 为什么做

现在群里的 Agent 只有被 @ 才回复。用户希望它能像真人一样，看到相关的话题自己决定要不要开口。用户建议用专门做判断的模型（Jev 这一类）来决定“回 / 不回”，再由 Agent 自己的模型写正文。

## 目标

主人可以给自己的 Agent 打开“主动参与”。打开后，群里有人说了和它相关的话，即使没 @ 它，它也可能回复。

## 不做

- 专属会话不受影响（那里本来就每条都回）。
- 不做“长时间无人值守地完成一项任务”，那是任务批次的事。
- 不让 Agent 因为别的 Agent 的消息而主动开口（Agent 之间仍然只有 @ 才接话）。这一条是为了不让几个 Agent 自己聊起来。

## 绝不能出现的情况

- 刷屏：真人聊几句，Agent 句句都插嘴。
- 几个 Agent 同时回答同一句话。
- 不知不觉把主人的点数用光。
- 判断模型出错时乱开口。

## 规则

**开关**

1. 每个 Agent 一个设置“主动参与群聊”，默认关闭，只有主人能改。关闭时行为和现在完全一样。
2. 被 @ 时照旧必定回复，不经过判断。

**什么时候判断**

3. 只有真人发的、没有 @ 任何 Agent 的消息才触发判断。
4. 连发的消息合并判断：有人连打几句，等他停下约 3 秒再判断一次，判断的对象是最新的那条。
5. 一条消息对群里所有打开了“主动参与”的 Agent 只做**一次**判断调用（一次调用里每个 Agent 一个问题）。

**怎么判断**

6. 给判断模型看的只有：群里最近的十几条消息（每个 Agent 只能包含它进群之后的），加上这个 Agent 的名字、简介和擅长领域。**不给它看人格文档**，也不给它看专属会话的任何内容。
7. 判断模型对每个 Agent 回答“它现在应该主动回复”的概率。概率最高、并且超过门槛的那一个 Agent 开口；最多一个。都没过门槛就谁也不回。
8. 门槛是全站配置，起始值按实测校准后确定（实测里“明显该回”的情况约 0.5，闲聊约 0.1）。主人可以给自己的 Agent 选“少说 / 适中 / 多说”三档，对应不同的门槛。
9. 判断模型出错、超时、返回看不懂的结果：一律当作不回。

**刹车**

10. 冷却：一个 Agent 主动回复之后，在这个群里至少隔 60 秒才会再主动回复（被 @ 不受冷却限制）。
11. 上限：每个 Agent 每小时最多主动回复 6 次（主人可改，范围 1–30）。
12. 第 2C 批的三道刹车照旧适用：按花费、连续条数、让 Agent 停下。按下“让 Agent 停下”后，主动回复也停，直到有真人再发言。
13. 主人暂停 Agent 后，它不会被判断，也不会主动回复。

**费用**

14. 判断的费用算谁的：**算站点的，不扣用户的点**。判断很便宜（约每万次 0.2 美元），按次向用户收费得不偿失，也会让用户不敢开。站点层面设每天的判断次数上限，超过后当天所有“主动参与”暂停并记录日志。
15. 判断之后真正写回复的那次调用，照常算 Agent 主人的。

**别人看到什么**

16. 主动回复和被 @ 的回复在群里看起来一样，不标“主动”。主人在自己 Agent 的回复下方那行小字里能看到“主动回复”字样。
17. 群成员看不到谁开了“主动参与”。

## 考虑过的做法

- **A. 判断模型先筛，再让 Agent 的模型写（本设计）。** 不开口时几乎不花钱；一次调用解决多个 Agent 抢话。
- **B. 直接让每个 Agent 的模型读每条消息，自己决定回不回。** 最像真人，但每条消息每个 Agent 都要调用一次大模型，贵而且慢；多个 Agent 各自决定，容易同时开口。不采用。
- **C. 关键词或规则匹配。** 便宜但很笨，容易误触发。不采用。

## 技术上的安排

- 判断模型走它自己的接口（`/systemone`），不是现有的四种对话接口。网关里加一个独立的小对接，配置里写它的地址和密钥变量；可以配两个渠道（官方和 CanalAPI），一个不通用另一个。
- 没有配置判断模型的部署，“主动参与”这个设置不出现。
- 校准：上线前准备几十条真实的群聊片段（该回的和不该回的），跑一遍看门槛定在哪里误判最少；这些片段做成可重跑的脚本。

## 请你决定的事

1. **第 14 条：判断的费用由站点承担，不扣用户点数。** 我的建议是这样；另一种是每次判断扣主人极少的点数。
2. **第 10、11 条的默认值**：冷却 60 秒、每小时最多 6 次。觉得太保守或太放开都可以改。
3. **不在范围里的那一条**：这一批不让 Agent 因为别的 Agent 的消息主动开口。你之前说过不应该严格禁止 Agent 互相接话——@ 接话已经有了；这里说的是“没被 @ 也接别的 Agent 的话”，我建议先不做，等看过主动参与的实际效果再放开。

## 验收

每条规则有自动化测试（判断模型一端用本机的假服务，能按指令返回各种概率、出错、超时）；另外对真实判断模型跑一遍校准脚本并记录结果；线上用真实模型在群里实际走一遍：相关的话题有 Agent 主动回复，闲聊没有，两个都相关时只有一个回复。
