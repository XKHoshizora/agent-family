# 一个账号、一个聊天入口

本批次目标：用户在 Element 内登录、加好友、管理自己的 Agent 和进入原生聊天，不再把 AF 工作台作为必经路径。旧讨论和资料保留；不把旧 AF 能力视为已验证的生产依赖。

## 复用与边界

- Element Web v1.12.35 的 Module API 扩展侧栏和登录入口；聊天、房间、附件、同步、设备验证与密钥恢复仍由 Element 原生实现。
- Synapse 保留账号、房间和联邦，启用标准 OIDC 单点登录。Better Auth 官方 OAuth Provider 负责协议，现有用户身份和密码继续有效；账号映射使用不可变用户 ID，不靠邮箱猜测合并。
- Agent 使用 Matrix SDK 管理独立账号、同步和加密；模型调用复用 AI SDK。AF 只负责经验证的关系、归属、授权和运行约束。
- 好友申请、聊天邀请、Agent 授权分别管理。加好友或入群不授予电脑、模型密钥、文件或他人资源权限。

## 用户流程

1. 一个聊天域名，使用现有 AF 账号登录一次，经 Synapse OIDC 进入 Element。原有 Matrix ID 和历史不变，不重置密钥。
2. 左侧“联系人”：显示自己的 Matrix ID，精确搜索用户、发送申请、接受/拒绝/撤回、删除、拉黑；接受后可进入 Element 原生私聊。普通外部 Matrix 用户仍可通过标准聊天邀请互通；应用好友状态不冒充 Matrix 标准能力。
3. 左侧“我的 Agent”：创建、编辑名称与职责、暂停/恢复、进入原生聊天，展示所属主人与能力。默认不使用电脑，不继承群权限。
4. Agent 群继续要求全部必要主人可见；不以未验证的原生群成员关系替代监督规则。未满足监督和授权条件时不得自动运行。

## 实现与验收

Codex 负责 Element 模块、好友/Agent 接入、部署和端到端验证；Claude Code Opus 5.5 xhigh 负责 OIDC 身份集成及针对性测试，随后交叉审阅。

验收重点：首次/再次登录同一身份；已有 Matrix ID 保持；错误账号组合拒绝；双人申请接受/拒绝/拉黑；Agent 创建归属不可越权；原生加密聊天中真实回复；暂停后不再调用模型；主人缺席时不运行；浏览器刷新恢复；新旧数据均保留。所有未通过的项目明确列为未交付，不用可点击页面代替真实功能。
