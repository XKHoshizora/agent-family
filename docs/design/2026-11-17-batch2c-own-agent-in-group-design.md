# 第 2C 批：把自己的 Agent 拉进群（简版设计）

日期：2026-11-17。状态：**用户已确认**（2026-11-17：群里任何成员都可以 @ 它）。

## 为什么做

试用第 2A 批时，用户两次碰到同一个限制：别人搜不到 Agent，也不能把 Agent 拉进群。完整的“Agent 社交”是第 3 批，工作量大。这里先切出规则最简单的一块：**主人把自己的 Agent 拉进自己所在的群**。主人本来就在群里，费用归属没有争议，所以可以很快做完。

## 目标

主人能把自己的 Agent 加进自己所在的群；群里的人 @ 它，它就在群里回复。

## 不做（留给第 3 批）

- 别人搜到、加好友、私聊我的 Agent。
- 把 Agent 拉进主人不在的群。
- Agent 之间互相对话。
- 群里对 Agent 的拉黑。

## 绝不能出现的情况

- Agent 出现在主人看不到的对话里。
- 别人通过群拿到 Agent 的人格文档、模型配置，或主人的密钥、余额。
- 几个 Agent 在群里互相接话停不下来。
- 群里的普通聊天不知不觉把主人的点数用光。

## 规则

**加入和离开**

1. 只有主人能把自己的 Agent 加进群，而且只能加进主人自己是成员的群。别人不能拉我的 Agent。
2. Agent 算一个群成员，计入 500 人上限，在成员列表里带“Agent”标记，并写明主人是谁。
3. 主人可以随时把它移出群；群的创建者也可以把它移出（和移出普通成员一样）。
4. 主人退群或被移出群，他的 Agent 自动一起离开。这样“Agent 参与的对话主人都看得见”始终成立。
5. Agent 被删除后自动离开所有群，它以前发的消息保留。

**什么时候回复**

6. 只有被 @ 才回复：消息里出现 `@它的账号名`。**群里任何成员都可以 @ 它**（用户决定）。每个 Agent 有一个开关“群里谁可以叫它”：所有成员（默认）或仅主人。没被 @ 的消息它不回复，也不花钱。
7. 一条消息 @ 了几个 Agent，各自回复一次。
8. **Agent 发的消息永远不会触发任何 Agent**，即使里面写了 @。这一批不存在 Agent 之间的对话。
9. Agent 暂停时不回复，被 @ 也不回复。
10. 沿用现有的保护：每个 Agent 在同一个会话里同时只处理一次回复，回复期间又被 @ 的合并成一次；每分钟回复次数有上限。（它可以同时在专属会话和某个群里各回复一次。）

**它能看到什么**

11. 只看到它进群之后的消息和附件，和后加入的真人一样。被移出再加回来，只看到重新加入之后的。
12. 回复时带上群里最近的对话（不只是 @ 它的那几条），放不下就丢掉最早的。它知道每条消息是谁发的。
13. 群里的对话和它的专属会话互不相通：群里的人问不出主人私下跟它说过什么。人格文档照常生效，但内容不会展示给群成员。

**费用**

14. 它在群里的每次回复都算主人的：用主人给它选的模型，扣主人的免费额度或余额，规则和专属会话完全一样。
15. 主人额度不够、模型出错、回复被限速时：主人看到原因和“重试”（和专属会话一样）；其他成员只看到一行“某某暂时无法回复”，不显示原因。

**别人能看到它的什么**

16. 群成员能看到：名字、头像、账号名、简介、擅长领域、主人是谁。看不到：人格文档、用的哪个模型、思考程度、是否自带供应商。
17. 群成员仍然不能搜索它、加它好友、和它私聊。

**这一批在群里不做的 Agent 功能**

18. 人格提议（“边聊边配置”）只在专属会话里有效，群里不解析。
19. “开始新话题”只属于专属会话。
20. 群里的回复不保存也不显示“思考过程”（思考内容常常会复述人格文档）。回复在群里不逐字显示：所有成员先看到“某某正在回复…”，写完后整条出现。逐字显示留到以后。

## 考虑过的做法

- **A. 被 @ 才回复（本设计）**：费用可控，行为可预期，也是常见聊天软件里机器人的做法。
- **B. 群里每条消息都让它判断要不要回**：更像真人，但每条消息都要调用一次模型，主人的点数很快用光，也容易刷屏。不采用。
- **C. 只有主人 @ 才回复**：最省钱，但群里别人用不了，拉进群的意义不大。作为第 6 条的备选，见下。

## 用户的决定

群里任何成员都可以 @ 它让它回复，费用算主人的。兜底手段：每分钟回复次数上限，主人可以随时暂停或移出它。

## 验收

每条规则都要有自动化测试，包括负向的：别人拉不了我的 Agent；主人退群后 Agent 不在群里；Agent 读不到进群前的消息；Agent 的消息不触发 Agent；没被 @ 不调用模型；群成员的任何接口都拿不到人格文档和模型配置；费用记在主人名下。
