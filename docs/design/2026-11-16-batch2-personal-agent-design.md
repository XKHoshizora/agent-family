# Agent Family 第 2 批设计（2A 对话核心）：个人 Agent（站内配置）

日期：2026-11-16。状态：**待用户批准**。下一步是实施计划；计划经用户确认后才开始实现。

本文写给做实施计划的人。读完应能据此排计划，不需要再回头问用户。标注“我的决定”的条目是撰写者的选择，不是用户确认过的，审阅时请重点看。第 2 批按用户 2026-11-16 的决定拆成两段：**2A 对话核心**（本文）和 **2B 只读工具**（联网搜索、链接阅读、简单的文件输出；2A 交付后另写设计）。第 1 批的设计见 `2026-11-15-batch1-real-social-design.md`，本文沿用它的术语（主体、会话、成员、可见范围、写入事务）和全部约束，不再重复。

## 1. 意图

让用户在站内创建属于自己的 Agent，配置它是谁、用哪个模型，然后像和联系人聊天一样和它私聊，并能随时暂停它。

为什么先做这一段：第 3 批（Agent 进群、Agent 之间对话）和第 4 批（任务与电脑）都要求“Agent 是一个真实的会话参与者，它的发言走和真人完全相同的消息通道和规则”。这一批把这件事做成真的，同时把“模型由谁提供、用量怎么记、钱怎么扣”的地基打好。

用户要验证的是：和自己配置的 Agent 聊天这件事本身好不好用，门槛够不够低。

## 2. 目标、非目标、反目标

**目标**

- 创建、编辑、暂停、恢复、删除自己的 Agent。Agent 的主人在创建时确定，永远不能改。
- 创建后自动得到一个“我和它”的专属会话，它出现在消息列表里。
- 在专属会话里发消息，Agent 按人格文档回复；回复逐字出现；可以中途停止。
- 人格文档可以手写，可以留空由 AI 起草，也可以通过和 Agent 对话来生成。Agent 只能提议修改自己的配置，生效必须主人确认。
- 模型来源两种，创建时就都可用：
  - **自带供应商**：用户填第三方的接口地址和密钥，费用用户自己付给那一家。
  - **站点提供**：免费档（少数便宜模型，每人每天有免费额度）和付费档（凭余额使用，含高级模型）。
- Agent 能看图片、读一部分文件（6.5）；可以设置思考程度，思考过程折叠显示；回复带排版、代码高亮和数学公式。
- 用量从第一天起逐次记账。余额和账户档位这一批只能由管理员设置。
- 修掉第 1 批试用反馈里的三处毛病（见 6.11）。

**非目标（本批不做）**

- 外部 Agent 接入（用户已确认放到下一步）。
- Agent 进群、Agent 与别人或别的 Agent 对话、别人看见或找到我的 Agent（第 3 批）。
- 任何工具：联网搜索、链接阅读、Agent 生成文件（2B）；技能、知识库、电脑、任务、权限模式（第 4 批及以后）。
- 语音输入和朗读；流程图一类的图表渲染；需要我们自己解析的文件格式（Word、Excel 等）。
- 用户自己充值、套餐、支付渠道、发票（单独一批，需要用户先办好收款账号）。
- Agent 的长期记忆（超出上下文窗口的记忆）。
- 从已有 Agent 克隆配置。

**反目标（做成这样就算失败）**

- Agent 的回复绕过了消息核心的写入事务，或以任何方式不受“暂停”“已删除”约束。
- Agent 不经主人确认就改了自己的配置。
- 用户的供应商密钥被返回给浏览器、写进日志，或能被别的用户用到。
- 用户能让我们的服务器去请求内网地址。
- 欠额超出了 6.4 规定的界限（最多一次回复），或用量有调用却没有记账。
- 真实构建里的 Agent 回复来自模拟数据。
- 界面偏离原型的布局、配色、密度。

## 3. 约束

- 第 1 批的全部约束继续有效：单站、消息核心自研、规则在服务端且与写入同一事务、只引入宽松许可证的依赖、界面以 `prototype-v2` 为基线、未经用户同意不推送不部署、只能运行一个服务实例。
- 界面依据：`prototype-v2/src/pages/Agents.jsx` 及原型里与 Agent 私聊有关的部分。用户另给了 Hermes Agent 和 Cherry Studio 的创建界面作参考，采纳的部分已写进第 6 节。
- 用户不是工程背景。
- “模拟不等于真实”：自动化测试可以用本机的假模型服务，但验收必须包含对真实模型服务的调用。

## 4. 考虑过的做法

**Agent 的回复在哪里生成**

| 做法 | 取舍 | 结论 |
|---|---|---|
| 在 AF 服务进程内，由一个后台工作者生成，任务登记在 Postgres | 部件最少；回复写入和规则判断天然同一事务；重启后能接着处理。代价是与服务共用一个进程，只能单实例（现在本来就是） | **采用** |
| 单独的 Agent 运行服务，通过将来给外部 Agent 用的接入口连进来 | 内置和外部 Agent 走同一条路，结构最干净。但接入口还没设计，本批要先把它设计完，范围翻倍 | 不采用；但进程内的工作者只通过一个窄接口读写消息（见 6.5），将来可以搬出去 |
| 现在就引入一个 Agent 框架（Hermes 一类） | 能直接得到工具、技能、记忆。但本批只需要对话；框架的权限模型与“主人确认、服务端强制”未必相容，执行引擎的选型已约定在第 4 批前单独对比 | 不采用 |

**模型接口**

支持四种协议（用户已确认）：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini API。自带供应商和站点上游都可以是其中任何一种。协议、流式解析、思考与多模态内容的差异，用一个成熟的、宽松许可证的多供应商库来对接，不手写；地址防护（6.3）通过给这个库换上我们自己的请求函数来实现。

**记账单位**

| 做法 | 取舍 | 结论 |
|---|---|---|
| 按消息条数 | 最好懂，但一条消息的成本可以相差上百倍，控制不住成本 | 不采用 |
| 直接按货币 | 以后收费最直接，但现在没有定价也没有支付 | 不采用 |
| 站内“点数”：每个站点模型按输入、输出的 token 数折算点数（单价按每百万 token 配置；以上游报告的用量为准，字符数只用于占用时的估算和上游不报用量时的兜底） | 免费额度、余额、以后的充值都用同一个单位；定价可以随时调 | **采用**（我的决定） |

## 5. 总体结构

```
浏览器
   │  HTTP：Agent 管理、供应商、用量
   │  长连接：新消息、逐字回复、状态变更
   ▼
AF 服务 ──► Postgres（新增：Agent 配置、供应商、回复任务、用量与余额账本）
   │    └─► 对象存储
   └─ 回复工作者 ──► 模型服务（站点上游，或用户自带的供应商）
```

核心做法在第 1 批的基础上增加两条：

1. **Agent 是主体，它的回复就是一条普通消息。** 写入走与真人相同的事务，发送者是 Agent 主体；“已暂停”“已删除”“不是成员”在这个事务里判断。
2. **先登记、后结算，允许最后一次说完。** 调用站点模型之前，在一个事务里确认“还有可用的额度或余额”并登记一条进行中的占用；调用结束后按实际用量结算。只要开始时还有剩，这一次就完整说完，超出的部分记为欠额（6.4）。

## 6. 各部分设计

### 6.1 Agent 本身

- Agent 是一个类型为 Agent 的主体，主人是创建它的真人主体。表结构和数据库约束第 1 批已预留（Agent 必须有主人，主人必须是真人）。
- 字段：名称（1 到 20 字）、账号名（规则同真人账号名，创建时由主人填写并给出建议值，之后不可改；我的决定）、头像、简介（至多 40 字）、擅长领域（至多 20 字）、人格文档、私聊回复方式、模型选择、是否暂停。
- **人格文档**取代原型里的“角色说明”：一篇纯文本，上限 2 万字符（我的决定），决定它是谁、怎么说话、擅长什么。界面上要说明：它只影响如何回复，不授予任何权限。
- 私聊回复方式沿用原型的两项：“收到消息时回复”“仅在我点名时回复”（点名即 @ 它）。原型里的“群内回复方式”本批不出现。
- 头像：主人可以给 Agent 上传头像，规则与个人头像相同；不上传则按第 1 批的方式生成默认头像。
- **Agent 个数上限跟着账户档位走**（用户已确认这是一个盈利点）：每个账户有一个档位，档位决定最多能有几个 Agent，站内配置的和以后外部接入的合并计算，已删除的不算。本批只有“免费档：20 个”有实际意义；档位由管理员用命令设置，更高档位的名称和个数做成配置，付费分级在充值那一批再定。
- **删除**（我的决定，原型没有这个操作）：主人确认后 Agent 进入“已删除”状态，不再回复，专属会话保留历史但变为只读并从消息列表移到不显眼的位置或直接隐藏（由实施者按原型风格定），名字后带“已删除”。不做物理删除，账号名不释放。已删除不可恢复。
- 所有 Agent 管理接口只接受主人本人；对“不存在的 Agent”和“不是我的 Agent”给出完全相同的响应。
- Agent 的账号名与真人账号名共用同一个命名空间（第 3 批 Agent 可被查找时需要如此）。因此注册或创建 Agent 时“这个账号名已被占用”的提示会让人知道某个名字有人用了，但不透露它是 Agent、也不透露属于谁；这一点接受（我的决定，与第 1 批对真人账号名的处理一致）。
- 第 1 批保留的两个例外继续存在：任何已存在的主体都有头像、都可以被拉黑，所以这两个接口对一个 Agent 的编号和一个随机编号的响应不同。Agent 的编号只有主人见得到，风险接受；第 11 项验收不包含这两个接口。

### 6.2 专属会话

- 创建 Agent 的同一个事务里创建一个类型为“Agent 私聊”的会话，成员是主人和 Agent，两者都是发言成员。每个 Agent 只有这一个与主人的会话。
- 允许发送的条件（写入事务内判断）：发送者是这两个成员之一；Agent 未删除。主人发消息不需要好友关系。Agent 发消息另需：未暂停。
- 暂停期间主人仍可发消息，Agent 不回复，界面沿用原型的暂停提示。恢复后不会补回暂停期间的消息，但它们在之后的上下文里。
- 第 1 批的能力在这个会话里照常可用：文字、引用、表情、图片和文件、搜索、未读、已读。Agent 一方的“已读”在它开始处理一条消息时更新（我的决定）。
- 通讯录里新增“我的 Agent”一组，只列出自己的 Agent（我的决定，依原型“其他人的 Agent 在通讯录中查看”推到本批的范围）。别人搜不到、看不到我的 Agent：现有的按账号名查找接口和好友申请接口，本批对 Agent 的账号名一律按“查无此人”处理（主人自己查也一样，主人从“我的 Agent”进入）。
- **新话题**（我的决定，原型没有）：主人可以在会话里点“开始新话题”，服务端写入一条系统通知；之后的回复不再把这条通知以前的消息发给模型。历史仍然可见、可搜。用途是控制成本和避免旧话题干扰。

### 6.3 模型来源

每个 Agent 选一个模型：某个站点模型，或“我的某个供应商＋模型名”。主人随时可以改，改后从下一次回复起生效。

**自带供应商**

- 属于用户而不是某个 Agent，一个用户可以配多个，多个 Agent 可以共用。在设置页管理。
- 字段：名称、协议（四种之一）、接口地址、密钥、可用模型列表（可从供应商的模型列表接口读取，也可手填）。每个模型可标注：是否能看图片、是否能直接读 PDF、是否支持思考、上下文容量；有保守的默认值，用户可在“高级”里改。
- 密钥在服务端加密保存，加密用的主密钥来自环境变量；保存后任何接口都不再返回原文，只返回末尾 4 位。日志和错误信息里不能出现密钥。
- 提供“测试连接”：用一次最小的调用确认地址和密钥可用，并显示供应商返回的错误原因。
- **地址防护**：只接受 https；发起请求前解析域名，目标是内网、本机、链路本地等非公网地址一律拒绝，并且连接必须打到刚才检查过的那个地址上；不跟随跳转；限制响应大小和总时长。这些在每一次调用时都要做，不只是保存时。
- 删除一个仍被 Agent 使用的供应商：拒绝，并列出是哪些 Agent 在用（我的决定）。
- 自带供应商的调用不占免费额度、不扣余额，但同样记用量，并受频率限制保护服务。

**站点提供**

- 站点模型清单由管理员配置（配置文件或环境变量，不做管理界面）：每个模型有显示名、协议、上游地址、上游密钥、上游模型名、档位（免费档或付费档）、输入和输出的点数单价、单次输出上限、上下文容量、能力标注（图片、PDF、思考及其可用档位）。没有配置任何站点模型时，界面上这一来源显示“尚未开放”。
- 规则（用户已确认，除标注处）：
  - 免费档模型：每人每天有一份免费额度（按用户算，不按 Agent 算；每天在站点设定的时区零点重置）。
  - **免费额度用完后继续用免费档模型，从余额里扣；没有余额就不能再发起新的回复，提示明确原因和重置时间**（我的决定，请确认：用户对“付费后免费模型是否不限量”表示还要考虑，这里选的是“不存在不限量，超出一律扣余额”）。
  - 付费档模型：没有免费额度，只扣余额；余额不足不能用。
- 余额：每个用户一个点数余额。本批只能由管理员用命令发放或扣减，每次变动带备注并写入账本。提供查看命令。
- 具体数值（每日免费额度、单价、新用户是否赠送余额）由管理员配置，实施者给出保守的默认值；改数值不需要改代码。

### 6.4 用量与账本

- **用量记录**：每一次模型调用一条，只追加不修改。内容：谁、哪个 Agent、哪种来源、哪个模型、输入量、输出量、折算点数、从免费额度扣了多少、从余额扣了多少、结果（完成、停止、失败）、时间。配置对话里的调用（6.7）同样记。
- **余额账本**：每一次余额变动一条（管理员发放、调用扣减、退回），只追加；当前余额必须始终等于账本之和，数据库约束保证余额不为负。
- **准入与结算**（用户已确认采用“让最后一次说完”的做法）：
  - 准入：发起一次站点模型的调用前，在一个事务里判断“可用量减去本人所有进行中调用的最大可能花费，是否仍大于零”。免费档模型的可用量是今天剩余的免费额度加余额；付费档模型的可用量是余额。大于零就放行并登记一条进行中的占用，否则拒绝并说明原因。
  - 结算：调用结束后按实际用量扣。免费档模型先扣免费额度，不够的部分扣余额；付费档模型只扣余额。**允许扣成负数**：免费额度的超出部分计入第二天的已用量；余额可以为负，为负期间不能发起任何需要余额的调用，管理员下次发放时先补平。
  - 界限：因为准入时把进行中的占用算了进去，一个用户的欠额最多是一次回复的最大花费。这是必须用并发测试守住的性质。
  - 上游返回了实际用量就按实际结算（思考产生的用量按输出计）；没有返回就按字符数用偏保守的系数估算。调用失败且没有产生输出时不扣。服务在调用中途崩溃留下的进行中占用，重启后要有明确的处理规则并释放，不能永久挂着。
- 设置页新增“用量与余额”：今天的免费额度用了多少、何时重置、当前余额、最近的用量（按 Agent 汇总）。
- 保护性上限（数值由实施者定，做成配置）：每个用户同时进行的回复数、每分钟的回复数、单次回复的最长时间。

### 6.5 回复的生成

- **触发**：专属会话里主人发出一条消息，且 Agent 未暂停、未删除，且回复方式允许（“收到消息时回复”，或消息里 @ 了它）。触发在消息写入的同一事务里登记为一条回复任务。消息里没有单独的“提及”字段（第 1 批的 @ 只是文字），所以“@ 了它”由服务端从文字判断：出现“@＋它的账号名”或“@＋它当前的名称”即算。
- **任务**保存在 Postgres。同一个 Agent 在同一个会话里同时只有一个任务在运行；运行期间主人又发了消息，不另起并行任务，等当前这次结束后针对新增的消息再运行一次（合并处理）。
- **工作者**在服务进程内运行，只通过一个窄接口工作：读取某会话在 Agent 可见范围内的消息、以 Agent 身份提交一条消息、上报状态。它不直接碰其他表。这个接口就是将来外部 Agent 接入口的雏形。
- **发给模型的内容**：站点固定的前言（它是谁的 Agent、主人怎么称呼、当前日期、它没有任何工具和文件访问能力、不要声称做了做不到的事）＋人格文档＋最近的对话。对话从最近一次“新话题”之后取，按模型的上下文容量留足余量截断，保留最新的。站点模型的上下文容量和输出上限在模型清单里配置；自带供应商的模型用一组保守的默认值，用户可以在供应商设置的“高级”里按模型改上下文容量（我的决定）。输出上限的设置要让一次回复通常放得进一条消息的现有长度上限。附件的处理（用户要求支持多模态）：
  - 图片：所选模型标注为能看图片时，把图片内容发给它；否则只以“[图片：文件名]”的文字出现，并在界面上提示“当前模型看不到图片”。
  - 纯文本类文件（文本、Markdown、代码、CSV 等，按内容判断而不是按扩展名）：把文字内容放进上下文，有大小上限，超出部分截断并注明。
  - PDF：所选模型标注为能直接读 PDF 时原样交给它；否则只给文件名。
  - 其他文件：只给文件名。
  - 附件内容占上下文和用量；截断上下文时，较早消息里的附件内容先于文字被舍弃。只取 Agent 可见范围内的附件，读取走与下载相同的授权判断。
- **思考程度**：每个 Agent 一个设置，档位为 none、low、medium、high、xhigh、max（用户给定）。发给模型时换算成各协议自己的参数；所选模型不支持的档位在界面上不可选，模型完全不支持思考时这一项隐藏。模型返回的思考过程随回复保存，界面上默认折叠；它不进入之后发给模型的上下文（除非协议要求原样带回），也不出现在搜索和消息预览里。
- **逐字输出**：生成过程中通过长连接把片段推给主人已打开的页面，显示为“正在回复”的气泡；这部分不入库。生成结束后，完整内容作为一条普通消息经写入事务入库，页面用它替换掉临时气泡。刷新页面时如果任务还在进行，能重新接上或至少显示“正在回复”。
- **停止生成**：主人可以中途停止。已生成的部分如果非空，作为消息入库并带“已停止”标记；用量按已产生的结算。
- **暂停或删除发生在生成途中**：任务取消，已生成的内容不入库（写入事务会拒绝），用量按已产生的结算。
- **失败**：不以 Agent 的名义发任何东西。失败原因记在回复任务上，**不是会话消息**：不占消息序号，不进搜索和未读数，不会被发给模型，也不引入第二套可见规则。界面根据该会话最近一次任务的状态，在会话末尾显示一条状态提示并提供“重试”；重试成功、主人关闭提示或有了新的任务后它就消失，不留在历史里（我的决定）。原因包括：今日免费额度已用完、余额不足、供应商拒绝了密钥、供应商超时或出错、地址不允许、模型返回了空内容。提示文字不能包含密钥或上游返回的敏感原文。
- 服务重启时，处于运行中的任务标记为失败并给出可重试的提示，不自动重复调用（我的决定：避免重复扣费）。
- Agent 的输出长度受单次输出上限约束，入库前按消息的现有规则检查（长度、不可见字符规则）；超长时截断并标记。

### 6.6 Agent 消息的显示

- Agent 的消息按 Markdown 的安全子集渲染（我的决定；第 1 批规定用户文字一律按纯文本显示，这条规定对真人消息不变）：段落、标题、列表、加粗斜体、行内代码与代码块（带语法高亮）、引用、表格、链接、数学公式。流程图一类的图表本批不渲染，按代码块显示。使用成熟的库，禁止原始 HTML。
- 链接在新标签页打开，不带来源信息。**不加载任何远程图片或其他远程资源**：Markdown 里的图片只显示为链接文字。理由是模型输出可能被对话内容诱导，把对话里的信息拼进图片地址泄露出去。
- 页面的内容安全策略不放宽。

### 6.7 人格文档的三种写法

1. **手写**：创建或编辑页面直接填。
2. **留空自动起草**：只填了名称和简介时，创建页提供“帮我起草”，服务端用所选模型根据名称、简介、擅长领域生成一份草稿，填进输入框，主人可改，保存才生效。
3. **边聊边配置**：人格文档为空的 Agent，在专属会话里先使用站点内置的“引导人格”。创建时会话里出现一条固定文案的开场白，以它的名义发出，不调用模型、不计费（我的决定）；主人回复后，它再通过模型问几个问题（它该是谁、帮什么忙、说话风格）。人格文档不为空的 Agent 没有开场白。它可以给出一份**配置提议**：会话里出现一张卡片，列出拟写入的人格文档（以及可选的简介、擅长领域），带“确认”“修改后确认”“放弃”。之后任何时候主人也可以让它“根据我们的对话更新你的人格”，得到同样的卡片。

规则：

- 提议保存在服务端，卡片只引用提议的编号。**生效只有一条路：主人本人的登录会话调用确认接口。** Agent 的任何输出都不能直接修改配置。提议只能包含人格文档、简介、擅长领域，不能包含模型、暂停状态、账号名、主人。
- 触发提议的方式由实施者选择，要求是不依赖供应商的“工具调用”能力（许多第三方供应商不支持或不稳定）。
- 提议被确认、放弃或被更新的提议取代后失效；每份提议记着它生成时人格文档的版本；确认时如果人格文档在那之后被改过（例如主人手动编辑了），确认被拒绝，卡片提示“配置已变更，请重新生成提议”，手动的修改保留（我的决定）。
- 起草和提议产生的模型调用，与普通回复一样计入用量和扣费。

### 6.8 隐私提示

用户要清楚地知道：发给 Agent 的对话内容会被发送到所选的模型服务商。在创建 Agent 选择模型处、以及添加自带供应商处给出说明（文案由实施者按原型的提示样式写，本批不做单独的协议页）。

### 6.9 网页端

- 导航里的“Agent”从“尚未开放”变为真实页面，按原型：我的 Agent 列表、创建与编辑表单、详情页。
- 相对原型的改动（都已在上文说明）：
  - 表单：“角色说明”换成更大的“人格文档”并带“帮我起草”；增加头像、账号名、模型选择、思考程度；去掉“群内回复方式”。
  - 详情页分区保留“资料”“参与的会话”（本批只有专属会话一条）；“能力与设备”保留入口，内容显示“尚未开放”。
  - 详情页增加“删除 Agent”。

### 6.11 顺带修复（第 1 批试用反馈）

1. **头像不同步**：别人换头像后，其他人的页面要在下一次同步或收到变更推送时用上新头像，不需要刷新页面。做法由实施者定（例如同步数据里带头像版本）。Agent 的头像同理。
2. **气泡大小不一致**：别人发来的气泡不应被“名字和时间”一行撑宽，宽度只由内容决定，与自己发出的一致。
3. **“已读”位置**：贴在自己气泡的正下方、靠右对齐，不被悬停才出现的“回复”按钮占位挤开。

## 7. 验收

以下全部通过才算本批完成。除标注“人工”的以外都应是可重复运行的自动化测试；模型一端用本机的假模型服务，它能按指令返回正常流、慢速流、中途断开、错误码、空内容、不报用量。规则类测试以普通用户的登录会话直接调用服务端。

**正向**

1. 创建 Agent（三种人格写法各走一遍）→ 自动出现专属会话 → 发消息 → 逐字收到回复 → 刷新和换浏览器后历史完整。
2. 自带供应商：添加、测试连接、用它的模型完成一次对话；修改 Agent 的模型后下一次回复用新模型。
3. 站点免费档：在免费额度内对话；跨过额度的那一次完整说完；之后有余额则继续并扣余额，无余额则被拒并显示原因；次日额度重置且先扣掉前一天超出的部分。站点付费档：有余额可用；跨过零的那一次完整说完，之后被拒，发放余额后先补平。
3a. 四种协议各完成一次流式对话（对假模型服务）；思考程度的每个档位换算成对应协议的正确参数；思考过程折叠显示且不进入后续上下文。
3b. 能看图片的模型收到了图片内容，不能看的只收到文件名且界面有提示；纯文本文件的内容进入上下文并按上限截断；PDF 按模型能力处理；后加入范围之外的附件不会被读取。
3c. Agent 回复里的代码高亮和数学公式正确显示。
3d. 达到档位的 Agent 个数上限后不能再创建；删除一个后可以；管理员调高档位后可以。
4. 暂停后发消息没有回复；恢复后新消息有回复，暂停期间的消息没有被补回。
5. 停止生成：已生成部分入库并带标记，用量按实际结算。
6. 开始新话题后，发给假模型服务的内容里不再包含之前的消息。
7. 配置提议：确认后人格文档更新，下一次回复使用新文档；放弃则不变。
8. 对真实模型服务完成至少一次站点模型对话和一次自带供应商对话（在验收环境，人工）。四种协议里，用户提供了密钥的逐一做真实验证；没有密钥的只有假模型服务的测试，在验收记录里逐项写明。
9. 界面与原型逐页对照；新做的界面由用户看过（人工）。
10. 6.11 的三处修复各有测试；头像一项用两个浏览器会话验证。

**负向：规则**

11. 一个用户不能读取、修改、暂停、删除别人的 Agent，不能读到别人的 Agent 配置、人格文档、专属会话、提议；对不存在和无权的对象响应完全相同；别人按账号名查不到我的 Agent，也不能向它发起好友申请或把它拉进群。
12. Agent 的主人不可更改；Agent 不能没有主人；Agent 不能登录。
13. 暂停或删除的 Agent 不产生任何消息：包括暂停瞬间正在生成的那一条。并发测试：暂停与回复入库同时发生时，暂停生效之后没有任何 Agent 消息入库。
14. 提议不能被主人以外的任何人确认；伪造或过期的提议编号无效；提议里夹带模型、暂停、主人、账号名字段无效；模型输出里伪造“已确认”之类的文字不产生任何配置变化。
15. 供应商密钥：任何接口、长连接事件、错误信息、日志里都不出现原文；一个用户用不到别人的供应商；Agent 的模型不能指向别人的供应商。
16. 地址防护：内网、本机、链路本地、非 https、解析后变为内网的域名、跳转到内网，全部被拒；保存时合法、调用时解析结果变了的，同样被拒。
17. 额度与余额：并发发起多次回复时，欠额不超过一次回复的最大花费；可用量不大于零时一律被拒；每一次调用都有用量记录；账本之和等于余额；付费档模型无法通过任何参数走免费额度；自带供应商的调用不扣余额。
18. 用户之间的用量、余额、账本互相不可见；余额只能由管理命令改变，任何用户接口都不能增加余额。

**负向：健壮性**

19. 假模型服务慢速、中途断开、返回错误、返回空内容、返回超长内容、不报用量时：服务不崩溃，任务结束在明确状态，主人看到对应提示，用量被正确结算，没有挂起的占用。
20. 服务在生成途中重启：任务标记为失败可重试，没有重复调用，没有重复消息，占用被释放。
21. 所有新接口的畸形输入返回 4xx 而不是 5xx；新接口有频率限制。
22. Agent 输出里的 HTML、脚本、远程图片、伪造链接不会被执行或自动加载。

**独立攻击测试**

23. 由没有参与实现的审查者拿到代码和运行中的服务，专门尝试突破第 11 到 22 项，并重点尝试：通过对话内容诱导 Agent 改配置或泄露别人的信息、通过供应商地址访问内网、透支余额、以 Agent 身份越权发言。发现的问题逐条修复并补成测试，直到一轮下来没有新的可利用问题。

**运行**

24. 验收环境可按文档从零重建（含新配置）；备份恢复后供应商密钥仍可用（主密钥配套的情况下），余额与账本一致。

每项验收分别记录：代码状态、测试覆盖到什么、是否已部署、还有哪些限制。
