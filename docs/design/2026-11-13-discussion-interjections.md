# 自由讨论中的用户插话

用户授权直接实现、测试、更新在线版。复用自由讨论运行、消息、SSE、权限与额度，不创建第二个并行任务。

- Web 在自由讨论运行时同时显示发送补充与停止。补充必须携带明确 runId，结束竞争返回错误且保留草稿，不能悄悄新建任务。每次提交使用客户端幂等 ID。
- 消息持久化到当前 run；保存目标伙伴、已回应目标、回应消息。用户点名优先于 AI 交棒和公平轮询；多次补充全部进入上下文，最新指定优先，尚未回应的其他目标随后处理。未点名补充由下一位回应。每人可按当前群写权限插话。
- 新输入中止当前发言的子请求，保留已生成片段并标记让出；不取消整个 run。后续工具禁止继续执行旧发言。已发送请求计费仍可能发生，插话不重置次数和轮数。新的补充重置无补充／重复／连续失败检测，未被回应的补充不被静默标为已处理。
- 根问题与所有待处理补充优先进入 48,000 字符起始对话上下文。每次仍受 12,000 字符消息限制；待处理补充最多 10 条，编码后合计预算 16,000 字符（含预留包装开销），超出时明确拒绝并保留草稿。已回应补充保留历史，后续仍优先读取近期用户要求。
- 若额度、轮数、取消、权限或重启阻止继续，补充保留并显示未回应状态，结束原因说明数量。不通过插话自动提高用户设置的上限。
- LINE 自由讨论中新的 /af 内容加入当前同绑定任务，立即确认，只由原任务最终发送一次结果；事件去重继续有效。LINE 不得插入 Web 任务。Web 向 LINE 发起的当前讨论补充，必须明确勾选分享；只共享该条消息及其被授权引用的内容，普通 Web 历史不进入 LINE 上下文。更换绑定后旧共享授权失效。

实施顺序：新增输入队列表与运行参与者／来源快照 → 子请求中断和优先调度 → 上下文与回应状态 → Web/LINE 接口和界面 → 测试／有限真实模型验收 → 备份发布及线上检查。

自检：不自动重启结束的任务、不增加每日额度、不把用户补充当成系统权限。已在上游执行的请求／工具不能撤回。
